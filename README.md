# Стоматологічна клініка «A-Dent» — концептуальна модель та вимоги

Навчальний проєкт: предметна область інформаційної системи приватної стоматологічної клініки. Репозиторій містить концептуальну ER-модель даних, вимоги до системи (EARS, user stories, Gherkin), use case діаграму та матрицю трасування. Система автоматизує запис пацієнтів на прийом, планування завантаження лікарів і кабінетів з урахуванням тривалості візитів, облік наданих послуг та контроль оплати рахунків.

**Базовий процес:** запис на прийом → прийом (лікар фіксує надані послуги) → формування рахунка → оплата повністю або частинами через зовнішню платіжну систему.

## Бізнес-логіка за ролями

* **Пацієнт:** записується на прийом до лікаря потрібної спеціальності (дата, час, кабінет), переглядає й скасовує свої записи, оплачує рахунок повністю або частинами, переглядає історію лікування.
* **Лікар:** має одну або кілька спеціальностей, бачить свій розклад, проводить прийоми в обраному кабінеті без накладання візитів і фіксує щонайменше одну надану послугу за прийом.
* **Адміністратор:** веде довідники спеціальностей, кабінетів і послуг, керує розкладом (запис і скасування від імені пацієнта), відстежує статуси оплат (не оплачено / частково / повністю) та ініціює повернення коштів.
* **Платіжна система** (зовнішній сервіс): обробляє платежі й повертає статус транзакції.

## Модель даних

Сім сутностей: **Пацієнт, Лікар, Спеціальність, Кабінет, Послуга, Прийом, Рахунок**.

* Усі ключі (PK/FK) мають єдиний концептуальний тип `uuid`.
* Зв'язки M:M: Лікар–Спеціальність і Прийом–Послуга (історична ціна послуги фіксується на момент надання).
* Зв'язки 1:M: Пацієнт, Лікар і Кабінет → Прийом. Прийом має не більше одного Рахунка (1:0..1).
* Критерії прийняття: 3NF, референційна цілісність, типізація ключів, відсутність дублювання.

## Вимоги та use cases

У `spec.md` описано: акторів та їхні цілі, 17 вимог у форматі EARS, 5 user stories з Gherkin-сценаріями та матрицю трасування «вимоги × use cases» (M:M). Вимога REQ-09 (SMS-нагадування) свідомо залишена непокритою — це межа MVP, бо потребує зовнішнього SMS-сервісу.
